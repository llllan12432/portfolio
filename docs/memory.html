Conversation memory

An experiment in remembering useful context between AI conversations, without treating every past detail as equally important.

Python / FastAPI / PostgreSQL / Supabase / Embeddings / MCP

Why I made it

I use AI assistants a lot, and it bothered me that they either forget everything between conversations or treat every old detail as equally important. I wanted to see if a system could hold on to what matters and let everyday details fade.

How it works

Permanent memories are loaded separately. Other memories are retrieved by semantic similarity, then ranked using similarity, emotional intensity, importance and age. Short-, medium- and long-term memories fade at different rates, with half-lives of about 5, 21 and 90 days.

The application combines retrieved memories with summaries and recent conversation before a model call. It also includes streamed responses, bounded active memory pools and MCP tools.

My part

I designed the memory model and the scoring, and built it with Claude Code doing much of the implementation. Codex later helped tidy the code for this public version.

See the ranking idea

Move the time slider and watch memories rise or drop in the ranking as they age. It runs in your browser on made-up memories, not real data.

Open ranking demonstration

What I’d do next

Emotion has the biggest weight, so a strong but off-topic memory can beat a more relevant one (the demo includes a case like this). Next I’d test the scoring on real retrieval results and tune the weights.
